# Skeleton cli workflow

## Framework Development setup

Manually create & activate a python virtual environment.
This environment is NOT managed by the Skeleton Framework!
```bash
python -m venv .my-auth-env
source .my-auth-env/Scripts/activate
```

Upgrade pip and install Framework Dependencies.
```bash
python -m pip install --upgrade pip
```

The -e flag installs the dependencies in editable mode.
`".[dev]"` ensures that dev dependencies are also installed.
including dev dependencies!
```bash
python -m pip install -e ".[dev]"
```

For VSCode users, generate (optional) mypy & markdown config.
```bash
python run.py --vscode --feature mypy
python run.py --vscode --feature --markdown
```

Create an experimental app folder.
```bash
mkdir app
cd app
```

Use the `help` or `readme` command to inspect the available commands.
```bash
python ../run.py --help
python ../run.py --readme (--section architecture | ...)
```

Use the `tree` operation to inspec the folder structure.
```bash
python ../run.py --tree --depth 5
```

For a VSCode workflow, generate (optional) mypy and markdown config.
```bash
python ../run.py --vscode --feature mypy
python ../run.py --vscode --feature --markdown
```

Follow the usual project setup instructions.
```bash
python ../run.py --config --profile (vanilla | react | solid | vue | svelte)
python ../run.py --init --verbose
python ../run.py --install --verbose
python ../run.py --start
```

Alternatively, use the quickstart command to generate a project.
```bash
python ../run.py --quickstart --profile (vanilla | react | solid | vue | svelte)
```

Preparer for release/publish.
```bash
python ../run.py --bump --verbose
python ../run.py --dist --verbose
python ../run.py --preview
```

Clean the Framework's build artifacts.
```bash
python ../run.py --purge
```

`*.egg-info`, `dist` & `app` are considered Framework build artifacts

## Integration Test / Demo setup

Generate the Framework's dist.
```bash
python run.py --dist --verbose
```

Generate a demo project folder with auto-configured `.venv`
Use the `--target` flag to specify the demo project folder.
```bash
python run.py --demo --target /path/to/demo/project --verbose
```

The demo `.venv` is generated by the Framework,
but is not a Framework-managed virtual environment.

The default project folder name is `./demo`
& it is included in the Framework's `.gitignore`.

Visit the generated project folder.
```bash
cd /path/to/demo/project
```

Activate the generated `.venv`.
```bash
source ./.venv/Scripts/activate
```

Now, the generated demo projet
can be used exactly like any
client project!

Check skeleton installation in `.venv`.
```bash
which skeleton
python -m pip show skeleton-framework
```

Check availablility of framework commands.
```bash
skeleton --help
skeleton --readme (--section architecture | ...)
```

Inspect the project folder structure.
```bash
skeleton --tree --depth 5
```

For VSCode users, generate appropriate mypy & markdown config.
```bash
skeleton --vscode --feature mypy
skeleton --vscode --feature --markdown
```

Follow the usualy project setup instructions.
```bash
skeleton --config --profile (vanilla | react | solid | vue | svelte)
skeleton --init --verbose
skeleton --install --verbose
skeleton --start
```

Alternative single/combined command
```bash
skeleton --quickstart --profile (vanilla | react | solid | vue | svelte)
```

Preparer for release/publish.
```bash
skeleton --bump --verbose
skeleton --dist --verbose
skeleton --preview
```

Clean the demo project's build artifacts.
```bash
skeleton --purge
```

## Client / Framework-user setup

Create & activate a (client) virtual environment.
```bash
python -m venv .my-venv
source .my-venv/Scripts/activate
```

This virtual environment is client-owned
and is, thus, not managed by the Framework.

Upgrade the client-owned pip &
install the Skeleton Framework.
```bash
python -m pip install --upgrade pip
python -m pip install skeleton-framework
```

Check whether the framework was installed.
```bash
which skeleton
python -m pip show skeleton-framework
```

Inspect the `help` command & check the `readme` docs.
```bash
skeleton --help
skeleton --readme (--section architecture | ...)
```

Check the client's project folder structure.
```bash
skeleton --tree --depth 5
```

For VSCode users, generate (optional) client's mypy and markdown config.
```bash
skeleton --vscode --feature mypy
skeleton --vscode --feature --markdown
```

Continue the usual workflow to generate client projects.
```bash
skeleton --config --profile (vanilla | react | solid | vue | svelte)
skeleton --init --verbose
skeleton --install --verbose
skeleton --start
```

Alternative single/combined command
```bash
skeleton --quickstart --profile (vanilla | react | solid | vue | svelte)
```

Prepare for release/publish.
```bash
skeleton --bump --verbose
skeleton --dist --verbose
skeleton --preview
```

Clean the client's project build artifacts.
```bash
skeleton --purge
```

The following are considered build artifacts,
but are configurable in the client's
`config/skeleton-project.json`:

- `dist`,
- `*.egg-info`,
- `node_modules`,
- `package-lock.json`


## Docs

### `--readme` cli examples ...

Print the complete README.
```bash
skeleton --readme
```

Print one section.
```bash
skeleton --readme --section architecture
```

Write the complete README to the current directory.
```bash
skeleton --readme --write README.md
```

Write one section to a separate file.
```bash
skeleton --readme --write architecture.md --section architecture
```

Write the complete README to another directory.s
```bash
skeleton --readme --write docs/README.md
```
